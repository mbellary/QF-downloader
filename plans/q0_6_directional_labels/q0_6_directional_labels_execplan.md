## Task Spec Snapshot (from quant_tasks.md)

### Description

Defines how directional prediction targets are derived from returns, including horizon selection, thresholding logic, volatility normalization, and regime conditioning.

### Objective

Ensure directional classification labels are economically meaningful, statistically stable, and consistent across training, validation, and live inference.

### Purpose

Define how directional prediction targets are constructed from returns in a way that is statistically stable, economically meaningful, and regime-aware.

### Business Use Cases

- Directional trading: predict up/down moves.
- Noise avoidance: do not trade weak signals.
- Regime awareness: direction only matters sometimes.
- Probabilistic decisions: support confidence-based trades.

### Data Providers

Data type required: returns, volatility, regime context.

Approved providers: Dukascopy (intraday FX), Stooq (long history), FRED (macro regime overlays).

Relevance: directional labels must be noise-aware and regime-conditioned.

### Example Data & Target

Example: return +0.0005 with volatility 0.0002 yields a `direction_label` of +1.

### Inputs

The task lists the following inputs (do not treat these as temporal dependencies):

- Return calculation rules: `/docs/quant/return_calculation.yaml` (Quant Q0.1)
- Session boundary rules: `/docs/quant/return_calculation.yaml` (Quant Q0.1)
- Regime conditioning rules: `/docs/quant/feature_intent_and_constraints.json` (Quant Q0.10/Q0.11; note naming mismatch vs `feature_constraints.json`)

### Global System Constraints

Must comply with the doctrine that “direction is downstream of noise and volatility” and must not dominate system objectives.

### Label Definition

Directional labels $Y_{dir} \in \{-1, 0, +1\}$ are defined by comparing the horizon return $r_{t\rightarrow t+h}$ against a volatility-scaled threshold $\theta(\sigma_t)$:

- $+1$ if $r_{t\rightarrow t+h} > \theta(\sigma_t)$
- $-1$ if $r_{t\rightarrow t+h} < -\theta(\sigma_t)$
- $0$ otherwise

### Horizon Specification

Allowed horizons: intrabar (e.g., 5m/15m), session-close, and fixed-bar lookahead (t+1, t+N). Horizons must align with session boundaries defined in Q0.1.

### Thresholding Rules

Default threshold: $\theta(\sigma_t) = k \cdot \sigma_t$. Fixed thresholds must be explicitly documented. Zero-threshold labels are disallowed unless explicitly approved.

### Regime Conditioning (Optional)

If regime labels exist, thresholds may vary by regime, and class balance statistics must be reported per regime.

### Deliverables

A. Normative specification artifacts (Quant-owned):

- `docs/quant/alpha_dir.yaml` MUST encode horizon options, volatility-scaled thresholds, class encoding {-1,0,+1}, regime conditioning rules, forbidden configurations.
- `docs/quant/alpha_dir.md` MUST explain why direction is downstream, the economics of the zero class, and interaction with $\sigma$ and $\epsilon$.

B. Derived artifact contracts (mandatory, generated downstream):

- `/targets/alpha_dir_labels.csv` MUST encode timestamp, horizon, direction_label, volatility_used, regime_id (if applicable).
- `/targets/alpha_dir_label_metadata.json` MUST encode threshold parameters, class balance stats, regime-conditional counts, leakage validation flags.

C. Schema registry entry:

- `/docs/quant/target_schemas/alpha_dir.yaml`
- `/docs/quant/target_schemas/alpha_dir.md`

### Outputs

- `/targets/alpha_dir_labels.csv`
- `/targets/alpha_dir_label_metadata.json`
- `/docs/quant/target_schemas/alpha_dir.yaml`
- `/docs/quant/target_schemas/alpha_dir.md`

### Acceptance Criteria

- No label leakage across horizons.
- Class balance reported per regime.
- Labels reproducible from specs alone.
- Quant sign-off required.

## Plan of Work

Create the normative spec and schema first, then the schema registry entry.

In `docs/quant/alpha_dir.md`, write the label definition as an unambiguous algorithm with:

- Required inputs and their alignment rules.
- Horizon configuration and allowed values.
- Thresholding policy, including the default $k \cdot \sigma_t$ rule and how fixed thresholds are represented.
- Regime-conditioning options and mandatory reporting (per-regime class balance).
- Leakage constraints: which timestamps are permitted for features vs label calculation.
- A worked example with small numbers to sanity-check sign and threshold behavior.

In `docs/quant/alpha_dir.yaml`, mirror the spec as machine-readable configuration, including enumerations for horizons and explicit fields for $k$, fixed thresholds, and regime-conditional overrides.

In `docs/quant/target_schemas/alpha_dir.yaml`, define the schema contract for the derived CSV and metadata JSON so downstream teams can validate conformance.
